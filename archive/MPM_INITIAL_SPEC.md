## MPM(My Portfolio Manager) Functional Requirements Specification

## 1. Summary
* 개요: 한국 주식 시장의 실시간/과거 데이터를 기반으로 다양한 기술적·재무적 지표를 분석하고, LLM을 활용한 리포트 요약 및 키워드 추출을 통해 사용자에게 정밀한 종목 추천 환경을 제공하는 인공지능 기반 주식 분석 및 포트폴리오 관리 프로그램.
* 시스템 구성:
* Frontend (FE): 사용자 화면 제공, 실시간 차트 렌더링, 검색 필터링 및 포트폴리오 관리 UI.
   * Backend (BE) Server: 실시간/과거 주가 데이터 파이프라인 구축, 금융 지표 연산 엔진, LLM 기반 데이터 가공(요약/키워드), 종목 추천 알고리즘 수행.

------------------------------
## 2. Data Requirements
안정적인 분석 환경을 위해 시스템이 수집, 생성, 관리해야 하는 데이터 정의입니다.
## 2.1. 외부 데이터 수집 (External Data Ingestion)

* 실시간 주가 데이터: 한국 주식 시장(KOSPI, KOSDAQ)의 현재가, 호가, 체결량, 거래대금 (1초 단위 동기화).
* 과거 주가 데이터: 종목별 일/주/월/년 단위의 시가, 고가, 저가, 종가(OHLCV) 및 수정주가 데이터.
* 주식 분석 리포트: 주요 증권사 및 리서치 기관의 공개 PDF 리포트 파일 혹은 텍스트 데이터 (증권사 파싱 API 또는 크롤러 활용).
* 기업 재무 데이터: 분기별/연도별 매출액, 영업이익, 당기순이익, 자산/부채총계 등 (FSS DART API 등 활용).

## 2.2. 내부 분석 및 LLM 생성 데이터 (Server-Side Processed Data)

* LLM 기반 리포트 가공 데이터:
* 리포트 요약: 한 줄 요약 및 핵심 내용 3줄 요약.
   * 키워드 데이터: 개별 리포트에서 추출한 핵심 타겟 키워드 (예: "반도체", "HBM", "어닝서프라이즈").
   * 감성 분석 점수: 리포트 어조에 따른 긍정(Bullish)/부정(Bearish) 스코어링.
* 시스템 계산 지표:
* 변동성 지표: 실시간/일일/주간 거래량 상승률 데이터.
   * 가격 포지션: 52주 신고가/신저가 달성 여부 및 이격도.
   * 밸류에이션 지표: PER, PBR, ROE, EV/EBITDA 등 실시간 주가 반영 연산 값.

------------------------------
## 3. Function Requirements
각 화면 및 모듈별 구체적인 프론트엔드 UI 요구사항과 백엔드 처리 로직입니다.
## 3.1. 주식 종목 목록 표시 (Stock List View)

* FE (화면 표시):
* 종목 정보 렌더링: 종목명, 종목코드(6자리), 현재가, 전일대비 등락률($\pm\%$), 실시간 거래량을 그리드 형태로 표시.
   * 화면 이동: 목록의 특정 종목 행(Row) 클릭 시, 해당 '종목 상세 페이지'로 라우팅.
* 목록 탭 종류 및 BE 로직:
* 오늘의 추천 탭: 서버에서 LLM 분석 및 거래량 조건(예: 당일 거래량 전일 대비 200% 이상 폭증 + 52주 신고가 근접 등)을 조합하여 산출된 Top 10 종목을 응답받아 표시.
   * 즐겨찾기(관심종목) 탭: 사용자가 북마크한 종목 리스트만 필터링하여 노출 (로컬스토리지 또는 사용자 DB 연동).

## 3.2. 종목 상세 정보 표시 (Stock Detail View)

* 주가 캔들 차트 (Chart UI):
* 일/주/년 단위 전환 탭 제공.
   * 차트 내 일목균형표 레이어(전행스팬, 후행스팬, 전환선, 기준선, 구름대) On/Off 토글 버튼 제공.
* 지표 분석 정보 표시:
* BE에서 계산된 현재 시점의 PER, PBR, ROE 값 표시.
   * 해당 종목이 현재 어떤 기술적 특징(예: '52주 신고가 달성', '일일 거래량 급증')을 가졌는지 태그(Tag) 형태로 상단 노출.
* AI 리포트 요약 및 키워드 영역:
* 해당 종목과 관련된 최신 리포트 목록 배치.
   * 리포트 선택 시 서버에서 생성한 'AI 요약본' 확장 컴포넌트 노출.
   * 추출된 키워드를 해시태그 형태로 바인딩하여 시각화.

## 3.3. 리포트 검색 (Report Search & Discovery)

* 검색 조건 필터 컴포넌트:
* 날짜 선택기(Date Picker): 리포트 게시일 기준 기간 검색 기능 (시작일~종료일).
   * 텍스트 검색창: 검색 대상을 '제목만', '본문 포함', '키워드 태그'로 분기할 수 있는 셀렉트 박스 포함.
* 검색 결과 컴포넌트:
* 검색 조건에 맞는 리포트 리스트와 매핑된 해당 주식 종목명을 함께 매칭하여 노출.
   * 즐겨찾기 즉시 추가: 검색 결과 목록 우측에 별 모양 아이콘($\star$)을 배치하여, 상세 페이지에 진입하지 않고도 즉시 사용자의 즐겨찾기(관심종목)에 추가/삭제 가능.

------------------------------
## 4. [추가] 시스템 제약 및 예외 처리 (Non-Functional & Exception Handling)
실제 비즈니스 로직 구동 시 발생할 수 있는 병목과 예외 상황에 대한 방어 로직입니다.

* 실시간 데이터 병목 처리: 주식 개장 시간(09:00~15:30) 동안 FE 차트와 현재가는 웹소켓(WebSocket) 또는 SSE(Server-Sent Events)를 통해 실시간 브로드캐스팅하며, 데이터 과부하를 막기 위해 디바운싱(Debouncing) 기술을 적용한다.
* 장마감 후 예외 처리: 주식 시장 마감 이후 시간 및 주말에는 '실시간 데이터 획득' 상태를 '종가 유지' 상태로 변경하고 화면에 "장마감" 안내 표시를 띄운다.
* LLM API 호출 제한 및 비용 최적화:
* 동일한 PDF 리포트에 대해 중복 분석 요청이 발생하지 않도록, 리포트 원본 파일의 해시(Hash)값을 ID로 삼아 분석 결과 데이터를 데이터베이스에 캐싱(Caching) 처리한다.
   * 사용자가 리포트를 조회할 때 이미 파싱된 캐시 데이터가 있다면 LLM을 재호출하지 않고 DB 값을 즉시 반환한다.
* 검색 결과 부재 시 예외 처리: 사용자가 입력한 키워드나 날짜 조건에 맞는 리포트가 시스템 내에 존재하지 않을 경우, 빈 화면 대신 *"조건에 맞는 리포트가 없습니다. 다른 키워드로 검색해 보세요."*라는 안내 문구를 출력한다.



## MPM(My Portfolio Manager) Free-Tier Architecture & API Spec

## 1. 무료 연동 외부 인프라 스펙 (Free-Tier Stack)
비용 발생을 막기 위해 무료 쿼터 및 프리티어 사양을 기반으로 선정했습니다.

* 증권사 API: 한국투자증권 KIS Developers Open API
* 선정이유: 모의투자 계좌 개설 시 실시간 및 과거 국내 주가 데이터를 무료로 제공합니다 [1, 2]. (웹소켓 실시간 체결가 지원) [3]
* LLM 엔진: Google Gemini 1.5 Flash API (AI Studio)
* 선정이유: 분당 15회(RPM), 일일 1,500회(RPD) 호출까지 텍스트/문서 분석을 완전 무료로 제공합니다. 대규모 리포트 PDF 입력이 가능한 콘텍스트 창을 지원합니다.
* Backend 호스팅: Render (Free Web Service) 또는 Supabase Edge Functions
* 선정이유: Render Free 플랜은 월 750시간 구동을 무료로 제공하여 웹 서버를 상시 가동할 수 있습니다. (※ 15분간 요청이 없으면 서버가 일시 정지(Sleep)되나 첫 요청 시 자동 깨어남)
* Database (DB): Supabase (Free Tier)
* 선정이유: 500MB의 PostgreSQL 관계형 데이터베이스를 평생 무료로 제공하며, Vector DB 기능(pgvector)도 내장되어 추후 리포트 시맨틱 검색 확장성이 뛰어납니다.

------------------------------
## 2. 데이터 흐름 및 비용 최적화 아키텍처
Gemini API와 증권사 API의 무료 제공 쿼터를 초과하지 않도록 철저한 캐싱(Caching) 전략을 명세화합니다.

[사용자 FE] <--- (Websocket/REST) ---> [Render BE 서버]


                                            |
                         +------------------+------------------+
                         | (데이터 존재 확인)                  | (API 쿼터 절약용)
                         v                                     v
               [Supabase PostgreSQL]                [외부 무료 API]
               - 주가 데이터 임시 캐싱               - 한국투자증권 (실시간 시세)
               - Gemini가 요약 완료한 리포트 저장      - Gemini AI (새 리포트 요약)


* 리포트 요약 캐싱: 새로운 PDF 리포트 발견 시에만 Gemini API를 호출하고, 결과물은 Supabase DB에 영구 저장합니다. 동일 리포트 요청 시 DB에서 꺼내와 Gemini API 호출 횟수를 0으로 만듭니다.
* 일일 주가 데이터 동기화: 과거 캔들 데이터는 장 마감 후 매일 밤 1회만 한국투자증권 API를 통해 수집하여 Supabase DB에 업데이트하고, 사용자 요청 시 DB 데이터를 반환하여 증권사 트래픽을 최소화합니다.

------------------------------
## 3. 백엔드 인터페이스 규격 (Core API Spec)
모든 API는 RESTful 표준을 따르며, 응답 포맷은 JSON 형식을 사용합니다.
## 3.1. [GET] /api/v1/stocks/recommend (오늘의 추천 종목 조회)

* Description: BE 내부 알고리즘(당일 거래량 폭증 + 52주 신고가 근접 조건)으로 필터링된 상위 10개 종목 리스트를 반환합니다.
* Response (200 OK):

{
  "status": "success",
  "data": [
    {
      "stock_code": "005930",
      "stock_name": "삼성전자",
      "current_price": 74200,
      "change_rate": 2.35,
      "volume": 14250300,
      "tags": ["거래량 급증", "52주 신고가 근접"]
    }
  ]
}

## 3.2. [GET] /api/v1/stocks/{stock_code}/detail (종목 상세 정보 및 지표 조회)

* Description: 선택한 종목의 기본 재무 지표 및 기술적 지표(일목균형표 연산 결과값 포함)를 제공합니다.
* Response (200 OK):

{
  "status": "success",
  "data": {
    "stock_code": "005930",
    "metrics": {
      "per": 15.4,
      "pbr": 1.2,
      "roe": 8.5

    "ichimoku": {
      "conversion_line": 73500,
      "base_line": 72000,

      "span_b": 70000,
      "position": "above_cloud"
    }
  }
}

## 3.3. [GET] /api/v1/reports/summary (리포트 검색 및 AI 요약 조회)

* Description: 검색 조건에 맞는 리포트 목록을 반환합니다. 데이터베이스에 캐싱된 요약본이 없을 경우에만 내부적으로 Gemini API(Free)를 호출해 저장 후 응답합니다.
* Query Parameters: keyword (검색어), start_date (YYYY-MM-DD), end_date (YYYY-MM-DD)
* Response (200 OK):

## 4. 무료 호스팅 제약 극복 방안 (Developer Guide)

* 서버 Sleep 현상 방지: Render Free 플랜은 15분간 요청이 없으면 서버가 잠듭니다. 이를 깨우기 위해 GitHub Actions(무료) 환경에 크론랩(Cron Job)을 설정하여 10분마다 서버의 헬스체크 앤드포인트(/api/v1/health)에 더미 요청을 보내 상시 활성화 상태를 유지시킵니다.
* DB 용량 관리 (500MB 제한): 과거 주가 데이터가 무한히 누적되면 용량이 초과될 수 있습니다. 분석에 필요한 최신 1~2년 치 일봉 데이터만 데이터베이스에 유지하고, 그 이전의 아주 오래된 데이터는 조회 요청 시 한국투자증권 API에서 실시간으로 직접 받아오도록 설계하여 DB 용량을 최소화합니다.
